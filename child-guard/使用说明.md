## 🔒 防关机清零（重要）
- 累计观看时间、连续观看计时、休息计时都会**自动保存到电脑上**（`~/.tv_guard/` 目录）
- 孩子**关电视、重启电视、拔电源**都不能清空计时：
  - 电视关机期间计时会“冻结”，但不清零；重新开机后接着算
  - 每天累计观看 120 分钟是写死在文件里的，关机也没用
  - 就算守护脚本本身重启，也会自动恢复之前的进度
- 只有**跨天**（过了午夜12点）才会重新开始新一天的额度

## 🚫 防绕过（关掉封面/偷开App都没用）
- 休息期间，孩子**按主页键关掉封面** → 封面会**自动重新弹出**
- 孩子**打开受控App**（快手TV/云视听）→ 立刻被强停，**进不去观看界面**，封面重新弹出
- 只有休息时间结束（或第二天），封面才会自动关闭、恢复正常观看

## 当前管控的App（只限这两个）
- **快手TV**（`com.kwai.tv.yst`）—— 孩子经常看
- **云视听**（`com.duokan.videodaily`）—— 孩子经常看
- **游戏大厅**（`com.cmgame.gamehalltv`）—— 限制游戏时间
- 其他App一律不限制

## 当前规则（v1.4 起，含夜间禁止）

### 时间段窗口（新增）
| 时段 | 规则 |
|---|---|
| **08:00 – 20:00** | 允许观看受控App，执行下面的"看30休息30"规则 |
| **20:00 – 次日 08:00** | **直接禁止**这3个受控App，到点自动恢复；不弹打扰，只有打开受控App才会被拦并显示夜间提示 |

> 夜间禁止是**全量禁止**：晚上8点后，这3个受控App 谁都不能打开；
> 其它App不受影响，依然可以正常用。

### 白天时段（08:00-20:00）的严格模式
- **只管这3个App**：快手TV、云视听、游戏大厅
- 累计观看 **30 分钟** → 强停App，**全屏弹出提醒页**（封面图+文字）
- 强制休息 **30 分钟**，休息期间偷开这3个App会立刻被停（检测间隔缩短到2秒），并重新弹提醒页
- 每天累计观看 **120 分钟** → 当天禁止这3个App，同样弹提醒页
- **严格累计计时**：切到别的App、电视关机、重启都不会清零本段计时，只有完成一次休息或跨天才归零
- **其他App完全不受影响**：随便用、随便看，不会被计时、不会被强停、不会被提醒页盖住

### 其他App为什么不受影响
- 守护只识别上面3个App的包名，其它App的前台一律不处理
- 休息期间弹提醒页的条件是"孩子回到桌面(空闲)"；如果他主动去用别的App，提醒页不会盖上去
- 强停+弹封面只在这3个App被打开时触发

## 🔧 v1.3 重要修正（2026-11-15）

之前电视重启后，**整个屏幕被"禁止观看"封面盖住**，看起来像电视完全不能用。
原因是两个问题叠加，已全部修复：

| 问题 | 原因 | 修复 |
|---|---|---|
| 开机后全屏封面挡住电视 | 旧逻辑「孩子**回到桌面(空闲)**就自动重新弹封面」。电视开机正停在桌面 → 封面立刻盖满全屏 | 改为**只有真的去开那 3 个受控App时才弹**。回到桌面、玩其它App 都不再弹 |
| 提醒页关不掉，像被锁死 | 提醒页把「返回键/菜单键」吞掉，还设了 `FLAG_KEEP_SCREEN_ON` 防止熄屏 | 返回键可正常退出；去掉常亮标志，电视能正常熄屏 |
| 提醒页弹不出来（只看到桌面） | 强停App后按了 HOME 键，桌面在提醒页**之后**才切到前台，把提醒页盖住了 | 去掉多余的 HOME 键，改为强停后稍等再弹提醒页 |

### 修正后的行为（实测）
```
打开受控App  →  最多5秒内被强停  →  弹出提醒页（带剩余时间倒计时）
按返回键     →  提醒页关闭，回到桌面，电视其它功能完全可用
回到桌面     →  不再自动弹提醒页（除非又去开受控App）
```

### 现在的规则（严格模式）
- **只管这3个App**：云视听快TV(`com.kwai.tv.yst`)、云视听(`com.duokan.videodaily`)、游戏大厅(`com.cmgame.gamehalltv`)
- **其他App完全不受影响**：随便用、随便看，不会被计时、不会被强停、不会被提醒页盖住
- 提醒页只是"提示"，随时可以按返回键关掉，不会锁死电视

## 修改规则 / 改提醒文字
1. 用编辑器打开 `tv_guard.sh` 改开头的 `WATCH_LIMIT_MIN`、`BREAK_MIN`、`DAILY_LIMIT_MIN` 等。
2. 想改提醒图文字：编辑生成脚本（用 PIL 重新生成 `reminder_1920x1080.png`），
   或直接替换 `reminder/res/drawable-nodpi/reminder.png`（必须是 1920x1080）。
3. 重新构建并安装提醒APK：
   ```bash
   cd reminder && ./build.sh
   cd .. && ./platform-tools/adb -s 192.168.6.168:5555 install -r reminder/reminder.apk
   ```
4. 重启守护：`./stop_tv_guard.sh` 然后 `nohup ./tv_guard.sh > /dev/null 2>&1 &`

## 提醒页 APK
- 包名 `com.example.reminder`，全屏显示 `reminder_1920x1080.png`
- 按返回键/菜单键无效，防止小朋友自己退出；由守护脚本自动控制显示/关闭

## 🔍 代码审查记录（2026-11-15）
| # | 问题 | 严重度 | 处理 |
|---|---|---|---|
| 1 | `trap cleanup EXIT INT TERM` 收到 SIGTERM 后 bash 会继续执行，**stop 脚本停不掉守护** | 严重 | 改为 `trap cleanup EXIT` + `trap 'cleanup; exit 0' INT TERM` |
| 2 | `start_tv_guard.sh` 无防重复启动，两个守护会互相覆盖状态文件 | 高 | 启动前检测已有进程则拒绝启动 |
| 3 | `stop_tv_guard.sh` 用字符串匹配 PID，脚本改名/绝对路径启动就失效 | 中 | 改为按 `(^|/)tv_guard\.sh` 匹配 PID，且不误伤 stop/start/watchdog 自身 |
| 4 | 守护进程崩溃后无人拉起，管理失效 | 高 | 新增 `watchdog.sh` + cron 每分钟自动检查并拉起 |
| 5 | 每日累计按分钟向上取整保存，每次重启最多多算 59 秒 | 低 | 改为存秒（`date=... seconds=... minutes=...`），并兼容旧格式 |
| 6 | 启动时 `hide_reminder` 会按主页键，打断电视上正在做的事 | 低 | 移除该按键，仅在强停视频时回桌面 |
| 7 | 提醒图用 `FIT_XY` 拉伸，电视分辨率变化会变形 | 低 | 改为 `FIT_CENTER` + 黑边 |
| 8 | 提醒页会出现在“最近任务”列表，孩子可从中切走 | 低 | 加 `android:excludeFromRecents="true"` |

> 审查后已全部修复并逐项实测通过（停止、重复启动、看门狗、提醒页显示均已验证）。
